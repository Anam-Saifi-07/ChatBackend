Connection Feature - Complete Documentation

Project: Chatting API (Spring Boot 3.4.4 + MySQL + JWT)
Feature: Personal (1-to-1) and Group Connection Requests
Version: v1.0 | Date: Nov 2026

What is this feature?
User A can send a connection request to User B (personal chat), or a user can request to join a group. When the other side accepts, they become connected and a chat room is ready. All requests are stored in one separate connection table.

1. Core Concept & Why

1.1 The Problem

Before this feature, two users were "connected" only if a chat room already existed between them. There was no way to:

  • Send a friend / connection request
  • Ask permission before starting a personal chat
  • Request to join a group (owner accepts/rejects)

1.2 The Solution - One New Table

Idea: Create ONE table called connection. Every request (personal or group) is one row in this table. A type column tells us which kind it is. A status column tells us the current state.
USER A BACKEND DATABASE | | | | "I want to chat with B" | | |------------------------> | INSERT connection row | | | (status = PENDING) | | |---------------------------> | | | | | USER B fetches pending list | | |<--------------------------- | | | | | USER B clicks ACCEPT | | | UPDATE status = ACCEPTED | | | CREATE room + 2 members | | |---------------------------> | | "You are now connected" | | |<------------------------ | |

1.3 Two Cases, One Table

Group (User joins Group)GROUPExisting group room idGroup owner/adminNo new room - requester added to existing RoomMembers

2. Database Design (Connection Table)

2.1 Table Schema

ColumnTypeNull?Meaning

sender_idVARCHAR(36)NoWho sent the request (FK -> person)
receiver_idVARCHAR(36)YesPersonal: target user. Group: group admin (FK -> person)
room_idVARCHAR(36)No (default "")Personal: empty string. Group: group room id (FK -> room)
statusVARCHAR(20)No (default PENDING)PENDING, ACCEPTED or REJECTED
created_atDATETIMENoAuto set on insert
updated_atDATETIMENoAuto update on change
Why empty string "" instead of NULL for room_id?
MySQL does NOT support partial unique indexes (unique only for some rows). So we use "" instead of NULL. This way ONE unique rule works for BOTH cases: UNIQUE(sender_id, room_id).
- Personal: every pair (A, "") can exist only ONCE -> duplicate personal request blocked.
- Group: every pair (A, groupId) can exist only ONCE -> duplicate join request blocked.

3. Workflow Diagrams

3.1 Case A - Personal Connection (1-to-1)

A sends request B accepts RESULT ------------------ ------------------------ ------------------------------ 1. INSERT connection 1. CHECK: I am the receiver? sender=A, receiver=B (only receiver can accept) room_id="", status=PENDING 2. UPDATE status=ACCEPTED WHERE id=? AND status=PENDING *** if 0 rows updated -> ERROR "already processed" (double-click safe) 3. Also accept reverse row (B->A) if it exists (race safety) 4. CREATE new room (is_group=false) 5. INSERT 2 room_members (A and B) *** ALL inside ONE transaction *** any failure -> full rollback
Reverse Request Race: What if A sends to B AND B sends to A at the same time?
Both rows are PENDING. When either side accepts, the code accepts both rows and creates only ONE room.

3.2 Case B - Group Join Request

User U joins Group G Admin accepts RESULT ---------------------- ------------------------ ------------------------------ 1. CHECK: G is a group? 1. UPDATE status=ACCEPTED CHECK: U not already WHERE id=? AND status=PENDING member? 2. CHECK: U already member? (skip if yes) CHECK: duplicate request? 3. INSERT 1 room_members row 2. FIND group admin (U, G, role=MEMEBER) 3. INSERT connection *** NO new room created sender=U, room=G, admin *** existing group room reused status=PENDING

3.3 Status State Diagram

send request | v +------------+ | PENDING | (initial state, default) +------------+ | | accept | | reject v v +------------+ +------------+ | ACCEPTED | | REJECTED | (final states - no more changes) +------------+ +------------+ Note: From ACCEPTED/REJECTED you can NEVER go back to PENDING. Guarded UPDATE only works while status = PENDING.

4. DB Constraints - Simple Explanation

What is a constraint? A constraint is like a bouncer at the door of your database. It stops bad data BEFORE it gets stored. You do not need to write checking code - the DB does it for you.
ConstraintReal Life ExampleHow it helps HERE
UNIQUE (sender_id, room_id)
uk_sender_room		 Bus ticket: seat A1 in bus-10 can be sold only ONCE. Same user cannot send TWO requests to the same person/group. Double-click on "Send" is blocked automatically. DB throws error, code shows "Duplicate request".
FOREIGN KEY
on sender_id, receiver_id, room_id		 Bank form: father's name must exist in the father registry. You cannot insert a connection with a fake or deleted room id / user id. Garbage data is impossible.
NOT NULL
on sender_id, room_id, status, type		 Exam form: roll number field cannot be left blank. Every request always has a sender and a status. No "empty" records.
DEFAULT
status = PENDING		 New form opens with a pre-selected option. When inserting, you can skip the status field - DB sets PENDING by itself.
INDEX
idx_receiver_status
idx_room_status		 Book index: find chapter fast without reading whole book. "Show my pending requests" stays fast even with 1 million rows.

4.1 What happens when duplicate is inserted?

Application code MySQL ---------------- ---- INSERT connection twice --> Table has UNIQUE(sender_id, room_id) Row 1: (A, "") - OK Row 2: (A, "") - REJECTED by DB <-- Exception: "Duplicate entry ... for key uk_sender_room" DataIntegrityViolationException Service catches it and returns friendly error

STEP 2 Connection Entity (Table)

Concept: The Entity class = the table. Hibernate reads it and creates the real MySQL table automatically (because ddl-auto=update is set in application.properties).

Create: entity/Connection.java

package chattingAPI.backend.entity;

import chattingAPI.backend.config.ConnectionStatus;
import chattingAPI.backend.config.ConnectionType;
import jakarta.persistence.*;
import lombok.*;
import org.hibernate.annotations.CreationTimestamp;
import org.hibernate.annotations.UpdateTimestamp;

import java.util.Date;

@Entity
@Table(
        name = "connection",
        uniqueConstraints = {
                // THE key rule: same sender + same room only ONCE
                @UniqueConstraint(name = "uk_sender_room",
                                  columnNames = {"sender_id", "room_id"})
        },
        indexes = {
                @Index(name = "idx_sender", columnList = "sender_id"),
                @Index(name = "idx_receiver_status", columnList = "receiver_id, status"),
                @Index(name = "idx_room_status", columnList = "room_id, status")
        }
)
@Getter @Setter @NoArgsConstructor @AllArgsConstructor @Builder
public class Connection {

    @Id
    @GeneratedValue(strategy = GenerationType.UUID)
    private String id;

    @Enumerated(EnumType.STRING)
    @Column(nullable = false, length = 20)
    private ConnectionType type;

    @Column(name = "sender_id", nullable = false, length = 36)
    private String senderId;

    @Column(name = "receiver_id", length = 36)
    private String receiverId;

    // personal -> "" , group -> real room id (empty string, NOT null)
    @Column(name = "room_id", nullable = false, length = 36)
    @Builder.Default
    private String roomId = "";

    @Enumerated(EnumType.STRING)
    @Column(nullable = false, length = 20)
    @Builder.Default
    private ConnectionStatus status = ConnectionStatus.PENDING;

    @CreationTimestamp
    @Column(name = "created_at", updatable = false)
    private Date createdAt;

    @UpdateTimestamp
    @Column(name = "updated_at")
    private Date updatedAt;
}

STEP 3 Connection Repository

Concept: Repository = the messenger between Java and MySQL. Spring Data JPA reads the method name and writes the SQL for you. You never write SQL for simple queries.

Create: repo/ConnectionRepo.java

package chattingAPI.backend.repo;

import chattingAPI.backend.config.ConnectionStatus;
import chattingAPI.backend.entity.Connection;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Modifying;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;
import org.springframework.transaction.annotation.Transactional;

import java.util.List;
import java.util.Optional;

public interface ConnectionRepo extends JpaRepository<Connection, String> {

    // incoming pending requests (my dashboard)
    List<Connection> findByReceiverIdAndStatus(String receiverId, ConnectionStatus status);

    // outgoing pending requests (I sent)
    List<Connection> findBySenderIdAndStatus(String senderId, ConnectionStatus status);

    // pending joins for a group
    List<Connection> findByRoomIdAndStatus(String roomId, ConnectionStatus status);

    // already accepted connection? (duplicate friend check)
    boolean existsBySenderIdAndReceiverIdAndStatus(String senderId, String receiverId,
                                                   ConnectionStatus status);

    // specific row find (used for reverse pending check)
    Optional<Connection> findBySenderIdAndReceiverIdAndStatus(String senderId, String receiverId,
                                                              ConnectionStatus status);

    // duplicate group join check
    Optional<Connection> findBySenderIdAndRoomId(String senderId, String roomId);

    // id + receiver check
    Optional<Connection> findByIdAndReceiverId(String id, String receiverId);

    /***************************************************************
     * GUARDED UPDATE - the most important query of this feature.
     * Only updates if current status is still PENDING.
     * Returns number of rows changed (0 or 1).
     * 0 means: someone already accepted/rejected - double click safe!
     ***************************************************************/
    @Modifying
    @Transactional
    @Query("UPDATE Connection c SET c.status = :status, c.updatedAt = CURRENT_TIMESTAMP "
         + "WHERE c.id = :id AND c.status = :expectedStatus")
    int updateStatusIfPending(@Param("id") String id,
                              @Param("status") ConnectionStatus status,
                              @Param("expectedStatus") ConnectionStatus expectedStatus);
}
Small fix applied in this file: original draft had : expectedStatus (space after colon) which breaks JPQL. Correct form is :expectedStatus.

STEP 6 Connection Service (all business logic)

Concept: Service = the brain. All rules live here: validation, duplicate checks, guarded updates, room creation. Everything that changes data is wrapped in @Transactional - meaning all DB changes succeed together, or ALL are rolled back (no half-updated data if the server crashes).

Create: Service/ConnectionService.java

package chattingAPI.backend.Service;

import chattingAPI.backend.DTO.ConnectionResponse;
import chattingAPI.backend.DTO.GroupJoinRequest;
import chattingAPI.backend.DTO.SendPersonalRequest;
import chattingAPI.backend.config.ConnectionStatus;
import chattingAPI.backend.config.ConnectionType;
import chattingAPI.backend.config.Roles;
import chattingAPI.backend.entity.*;
import chattingAPI.backend.repo.*;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.List;
import java.util.stream.Collectors;

@Service
public class ConnectionService {

    private final ConnectionRepo connectionRepo;
    private final PersonRepo personRepo;
    private final RoomRepo roomRepo;
    private final RoomMemberRepo roomMemberRepo;

    public ConnectionService(ConnectionRepo connectionRepo, PersonRepo personRepo,
                             RoomRepo roomRepo, RoomMemberRepo roomMemberRepo) {
        this.connectionRepo = connectionRepo;
        this.personRepo = personRepo;
        this.roomRepo = roomRepo;
        this.roomMemberRepo = roomMemberRepo;
    }

    // ==================== PERSONAL ====================

    @Transactional
    public ConnectionResponse sendPersonalRequest(SendPersonalRequest request, String currentUsername) {
        Person sender = personRepo.findByName(currentUsername)
                .orElseThrow(() -> new RuntimeException("User not found"));
        Person receiver = personRepo.findById(request.getReceiverId())
                .orElseThrow(() -> new RuntimeException("Receiver not found"));

        // rule 1: no self request
        if (sender.getId().equals(receiver.getId())) {
            throw new RuntimeException("Khud ko request nahi bhej sakte");
        }

        // rule 2: already connected in either direction?
        boolean alreadyConnected =
                connectionRepo.existsBySenderIdAndReceiverIdAndStatus(
                        sender.getId(), receiver.getId(), ConnectionStatus.ACCEPTED)
             || connectionRepo.existsBySenderIdAndReceiverIdAndStatus(
                        receiver.getId(), sender.getId(), ConnectionStatus.ACCEPTED);
        if (alreadyConnected) {
            throw new RuntimeException("Pehle se connected ho");
        }

        // rule 3: reverse pending? (B already sent to A) -> accept both instantly
        boolean reversePending = connectionRepo
                .findBySenderIdAndReceiverIdAndStatus(
                        receiver.getId(), sender.getId(), ConnectionStatus.PENDING)
                .isPresent();
        if (reversePending) {
            acceptBothSides(sender.getId(), receiver.getId());
            Connection connection = connectionRepo
                    .findBySenderIdAndReceiverIdAndStatus(
                            sender.getId(), receiver.getId(), ConnectionStatus.ACCEPTED)
                    .orElseThrow();
            return toResponse(connection);
        }

        // rule 4: duplicate pending same direction?
        boolean duplicatePending = connectionRepo
                .findBySenderIdAndReceiverIdAndStatus(
                        sender.getId(), receiver.getId(), ConnectionStatus.PENDING)
                .isPresent();
        if (duplicatePending) {
            throw new RuntimeException("Request already pending hai");
        }

        // save (DB unique constraint is the final safety net)
        Connection connection = Connection.builder()
                .type(ConnectionType.PERSONAL)
                .senderId(sender.getId())
                .receiverId(receiver.getId())
                .roomId("")
                .status(ConnectionStatus.PENDING)
                .build();
        try {
            connection = connectionRepo.save(connection);
        } catch (Exception e) {
            throw new RuntimeException("Duplicate request hai");
        }
        return toResponse(connection);
    }

    @Transactional
    public ConnectionResponse acceptConnection(String connectionId, String currentUsername) {
        Person current = personRepo.findByName(currentUsername)
                .orElseThrow(() -> new RuntimeException("User not found"));

        Connection connection = connectionRepo.findById(connectionId)
                .orElseThrow(() -> new RuntimeException("Request nahi mili"));

        // rule: only the RECEIVER can accept
        if (!current.getId().equals(connection.getReceiverId())) {
            throw new RuntimeException("Sirf receiver accept kar sakta hai");
        }

        // GUARDED UPDATE - double click protection
        int updated = connectionRepo.updateStatusIfPending(
                connectionId, ConnectionStatus.ACCEPTED, ConnectionStatus.PENDING);
        if (updated == 0) {
            throw new RuntimeException("Request already processed ho chuki hai");
        }
        connection.setStatus(ConnectionStatus.ACCEPTED);

        if (connection.getType() == ConnectionType.PERSONAL) {
            acceptBothSides(connection.getSenderId(), connection.getReceiverId());
        } else {
            addMemberToGroup(connection);
        }
        return toResponse(connection);
    }

    @Transactional
    public ConnectionResponse rejectConnection(String connectionId, String currentUsername) {
        Person current = personRepo.findByName(currentUsername)
                .orElseThrow(() -> new RuntimeException("User not found"));

        Connection connection = connectionRepo.findById(connectionId)
                .orElseThrow(() -> new RuntimeException("Request nahi mili"));

        if (!current.getId().equals(connection.getReceiverId())) {
            throw new RuntimeException("Sirf receiver reject kar sakta hai");
        }

        int updated = connectionRepo.updateStatusIfPending(
                connectionId, ConnectionStatus.REJECTED, ConnectionStatus.PENDING);
        if (updated == 0) {
            throw new RuntimeException("Request already processed ho chuki hai");
        }
        connection.setStatus(ConnectionStatus.REJECTED);
        return toResponse(connection);
    }

    // ==================== GROUP ====================

    @Transactional
    public ConnectionResponse sendGroupJoinRequest(GroupJoinRequest request, String currentUsername) {
        Person sender = personRepo.findByName(currentUsername)
                .orElseThrow(() -> new RuntimeException("User not found"));

        Room room = roomRepo.findById(request.getRoomId())
                .orElseThrow(() -> new RuntimeException("Group nahi mila"));

        if (!Boolean.TRUE.equals(room.getIsGroup())) {
            throw new RuntimeException("Ye group nahi hai");
        }
        if (roomMemberRepo.existsByPersonIdAndRoomId(sender.getId(), room.getId())) {
            throw new RuntimeException("Pehle se member ho");
        }
        boolean duplicate = connectionRepo
                .findBySenderIdAndRoomId(sender.getId(), room.getId()).isPresent();
        if (duplicate) {
            throw new RuntimeException("Request already pending hai");
        }

        // find the group admin (first ADMIN member)
        String ownerId = roomMemberRepo.findByRoomId(room.getId()).stream()
                .filter(m -> m.getRole() == Roles.ADMIN)
                .map(m -> m.getId().getPersonId())
                .findFirst()
                .orElseThrow(() -> new RuntimeException("Group admin nahi mila"));

        Connection connection = Connection.builder()
                .type(ConnectionType.GROUP)
                .senderId(sender.getId())
                .receiverId(ownerId)
                .roomId(room.getId())
                .status(ConnectionStatus.PENDING)
                .build();
        try {
            connection = connectionRepo.save(connection);
        } catch (Exception e) {
            throw new RuntimeException("Duplicate request hai");
        }
        return toResponse(connection);
    }

    // ==================== FETCH ====================

    public List<ConnectionResponse> getPendingIncoming(String currentUsername) {
        Person current = personRepo.findByName(currentUsername)
                .orElseThrow(() -> new RuntimeException("User not found"));
        return connectionRepo.findByReceiverIdAndStatus(current.getId(), ConnectionStatus.PENDING)
                .stream().map(this::toResponse).collect(Collectors.toList());
    }

    public List<ConnectionResponse> getSentPending(String currentUsername) {
        Person current = personRepo.findByName(currentUsername)
                .orElseThrow(() -> new RuntimeException("User not found"));
        return connectionRepo.findBySenderIdAndStatus(current.getId(), ConnectionStatus.PENDING)
                .stream().map(this::toResponse).collect(Collectors.toList());
    }

    public List<ConnectionResponse> getGroupPendingRequests(String roomId, String currentUsername) {
        Person current = personRepo.findByName(currentUsername)
                .orElseThrow(() -> new RuntimeException("User not found"));

        // only the group admin can see join requests
        boolean isAdmin = roomMemberRepo.findByRoomId(roomId).stream()
                .anyMatch(m -> m.getRole() == Roles.ADMIN
                        && m.getId().getPersonId().equals(current.getId()));
        if (!isAdmin) {
            throw new RuntimeException("Sirf admin dekh sakta hai");
        }
        return connectionRepo.findByRoomIdAndStatus(roomId, ConnectionStatus.PENDING)
                .stream().map(this::toResponse).collect(Collectors.toList());
    }

    // ==================== HELPERS ====================

    // accept BOTH directions (handles A->B and B->A race), then make ONE room
    private void acceptBothSides(String personA, String personB) {
        connectionRepo.findBySenderIdAndReceiverIdAndStatus(
                        personA, personB, ConnectionStatus.PENDING)
                .ifPresent(c -> connectionRepo.updateStatusIfPending(
                        c.getId(), ConnectionStatus.ACCEPTED, ConnectionStatus.PENDING));
        connectionRepo.findBySenderIdAndReceiverIdAndStatus(
                        personB, personA, ConnectionStatus.PENDING)
                .ifPresent(c -> connectionRepo.updateStatusIfPending(
                        c.getId(), ConnectionStatus.ACCEPTED, ConnectionStatus.PENDING));
        createPersonalRoom(personA, personB);
    }

    // create 1-to-1 room only if one doesn't exist already
    private void createPersonalRoom(String personA, String personB) {
        boolean roomExists = roomMemberRepo.findByPersonId(personA).stream()
                .filter(m -> Boolean.FALSE.equals(m.getRoom().getIsGroup()))
                .anyMatch(m -> roomMemberRepo.findByRoomId(m.getRoom().getId()).stream()
                        .anyMatch(m2 -> m2.getId().getPersonId().equals(personB)));
        if (roomExists) return;

        Person userA = personRepo.findById(personA).orElseThrow();
        Person userB = personRepo.findById(personB).orElseThrow();

        Room room = roomRepo.save(Room.builder().name("").isGroup(false).build());

        roomMemberRepo.save(RoomMembers.builder()
                .id(new RoomMembers.RoomMemberId(userA.getId(), room.getId()))
                .person(userA).room(room).role(Roles.MEMEBER).build());
        roomMemberRepo.save(RoomMembers.builder()
                .id(new RoomMembers.RoomMemberId(userB.getId(), room.getId()))
                .person(userB).room(room).role(Roles.MEMEBER).build());
    }

    // group accept -> add requester into EXISTING room_members
    private void addMemberToGroup(Connection connection) {
        Room room = roomRepo.findById(connection.getRoomId())
                .orElseThrow(() -> new RuntimeException("Group nahi mila"));
        if (!Boolean.TRUE.equals(room.getIsGroup())) {
            throw new RuntimeException("Ye group nahi hai");
        }
        if (roomMemberRepo.existsByPersonIdAndRoomId(connection.getSenderId(), room.getId())) {
            return; // already member - do nothing
        }
        Person requester = personRepo.findById(connection.getSenderId()).orElseThrow();
        roomMemberRepo.save(RoomMembers.builder()
                .id(new RoomMembers.RoomMemberId(requester.getId(), room.getId()))
                .person(requester).room(room).role(Roles.MEMEBER).build());
    }

    private ConnectionResponse toResponse(Connection c) {
        ConnectionResponse res = new ConnectionResponse();
        res.setId(c.getId());
        res.setType(c.getType());
        res.setSenderId(c.getSenderId());
        res.setReceiverId(c.getReceiverId());
        res.setRoomId(c.getRoomId());
        res.setStatus(c.getStatus());
        res.setCreatedAt(c.getCreatedAt());
        personRepo.findById(c.getSenderId())
                .ifPresent(p -> res.setSenderName(p.getName()));
        if (c.getRoomId() != null && !c.getRoomId().isEmpty()) {
            roomRepo.findById(c.getRoomId())
                    .ifPresent(r -> res.setRoomName(r.getName()));
        }
        return res;
    }
}

STEP 7 Connection Controller (HTTP endpoints)

Concept: Controller = the door. It only: (1) receives the URL, (2) gets the current user from JWT via authentication.getName(), (3) calls the service, (4) returns the response. NO business logic here. Pattern is exactly like the existing ChatController2.

Create: controller/ConnectionController.java

package chattingAPI.backend.controller;

import chattingAPI.backend.DTO.*;
import chattingAPI.backend.Service.ConnectionService;
import jakarta.validation.Valid;
import org.springframework.http.ResponseEntity;
import org.springframework.security.core.Authentication;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/api/v2/connections")
public class ConnectionController {

    private final ConnectionService connectionService;

    public ConnectionController(ConnectionService connectionService) {
        this.connectionService = connectionService;
    }

    // 1. send personal connection request
    @PostMapping("/personal")
    public ResponseEntity<ConnectionResponse> sendPersonalRequest(
            @Valid @RequestBody SendPersonalRequest request,
            Authentication authentication) {
        return ResponseEntity.ok(
                connectionService.sendPersonalRequest(request, authentication.getName()));
    }

    // 2. incoming pending requests
    @GetMapping("/personal/pending")
    public ResponseEntity<List<ConnectionResponse>> getPendingIncoming(
            Authentication authentication) {
        return ResponseEntity.ok(
                connectionService.getPendingIncoming(authentication.getName()));
    }

    // 3. outgoing pending requests
    @GetMapping("/personal/sent")
    public ResponseEntity<List<ConnectionResponse>> getSentPending(
            Authentication authentication) {
        return ResponseEntity.ok(
                connectionService.getSentPending(authentication.getName()));
    }

    // 4. accept (personal OR group - both use same endpoint)
    @PostMapping("/{id}/accept")
    public ResponseEntity<ConnectionResponse> acceptConnection(
            @PathVariable String id, Authentication authentication) {
        return ResponseEntity.ok(
                connectionService.acceptConnection(id, authentication.getName()));
    }

    // 5. reject
    @PostMapping("/{id}/reject")
    public ResponseEntity<ConnectionResponse> rejectConnection(
            @PathVariable String id, Authentication authentication) {
        return ResponseEntity.ok(
                connectionService.rejectConnection(id, authentication.getName()));
    }

    // 6. group join request
    @PostMapping("/group/join")
    public ResponseEntity<ConnectionResponse> sendGroupJoinRequest(
            @Valid @RequestBody GroupJoinRequest request,
            Authentication authentication) {
        return ResponseEntity.ok(
                connectionService.sendGroupJoinRequest(request, authentication.getName()));
    }

    // 7. group pending requests (admin only)
    @GetMapping("/group/{roomId}/requests")
    public ResponseEntity<List<ConnectionResponse>> getGroupPendingRequests(
            @PathVariable String roomId, Authentication authentication) {
        return ResponseEntity.ok(
                connectionService.getGroupPendingRequests(roomId, authentication.getName()));
    }
}

7. Edge Cases & How They Are Handled

#Edge CaseWhat could go wrongProtection (layer)
1 Double-click "Send" Two identical PENDING rows Service pre-check + DB UNIQUE(uk_sender_room) constraint (final net)
2 Reverse race: A→B and B→A same time Two rows, two rooms created On send: reverse-pending detected -> auto accept both. On accept: acceptBothSides() accepts both rows, createPersonalRoom() checks existing room first -> only ONE room
3 Double-click "Accept" Room created twice Guarded UPDATE (WHERE status='PENDING') - 2nd call gets 0 rows -> error "already processed"
4 Server crash mid-accept Status changed but room not created (inconsistent) Whole accept runs in ONE @Transactional - crash means full rollback, data stays consistent
5 Wrong user accepts Stranger approves my request Service checks currentUserId == receiverId
6 Join group where already member Duplicate room_members row Pre-check existsByPersonIdAndRoomId + skip inside addMemberToGroup
7 Self request (A→A) Nonsense row Service check: sender != receiver
8 Request to deleted user/group Orphan data Foreign keys + service orElseThrow checks
9 Non-admin sees group join list Privacy issue getGroupPendingRequests verifies ADMIN role
10 No JWT token Unauthorized access Spring Security filter chain (config already protects /api/v2/**)
11 Accept after REJECTED State goes backwards Guarded update only works from PENDING -> returns 0 rows
12 Existing DM room already there Second 1-to-1 room for same pair createPersonalRoom() first searches for existing non-group room between both users

9. Future Recap - Quick Context (for AI or new developer)

One paragraph summary:
The Connection feature adds a separate connection table to store personal (1-to-1) and group join requests. A single table with type (PERSONAL/GROUP) and status (PENDING/ACCEPTED/REJECTED) columns handles both cases. room_id="" for personal and real room id for group - this allows ONE unique constraint uk_sender_room(sender_id, room_id) to block all duplicates at DB level. Accept is a guarded UPDATE (WHERE status='PENDING') which prevents double-click bugs, and the whole accept operation runs in a transaction: personal accept creates a new 1-to-1 Room plus 2 RoomMembers; group accept simply inserts 1 RoomMembers row into the existing group room.

9.2 Key Decisions (why, not what)

  • Empty string "" instead of NULL for room_id - MySQL has no partial unique indexes; "" lets one unique rule cover both cases.
  • Enums in config package - project convention (Roles already lives there), not in entity package.
  • Service takes currentUsername (not id) - matches existing ChatService pattern; JWT subject is person.name.
  • RoomMembers uses composite key - must build with new RoomMembers.RoomMemberId(personId, roomId) + person + room entities (matches ChatService.createRoom).
  • Guarded UPDATE returns int - 0 rows = already processed; this is the single source of truth for double-click protection.
  • Connection rows are NEVER deleted - they are the audit trail (status flips to ACCEPTED/REJECTED).
  • Guarded note: role enum value is Roles.MEMEBER (original project typo) - do not "fix" it, existing DB data depends on it.

9.3 Known Gaps / Future Improvements

  • No REJECTED-list endpoint (rejected history can be added with same repo method pattern)
  • No WebSocket push for new request notifications (can use SimpMessagingTemplate to /topic/user.{id})
  • Group: no leave / kick / admin transfer endpoints yet
  • Personal accept after reject requires a fresh request (state machine intentionally one-way)
  • JWT secret is hardcoded in JwtTokenProvider - should move to environment variable in production
